### Owner: "what else could be worked on?" then "yeah churn on the f-strings work now"

Offered only CPU work that stays off the GPU, Maya, Blender and the orchestrator while the owner plays. The f-string
pass was the pick. A scan by AST (not grep, since many calls span lines) found 71 lazy `%`-format log calls in 20
files; a converter rewrote 67 and left 4 to hand (starred arguments, a `%s` with a tuple). Fourteen came out over the
line limit because adjacent string literals had merged into one: those were wrapped, and the seven with awkward
expressions got a named local first (a `join` inside an f-string reads badly). The whole diff was read for
placeholder-to-argument order; `%g`, `%.2f`, `%r` mapped to `:g`, `:.2f`, `!r`.

Ruff has no rule for the policy: its logging rules flag the f-string form, never the lazy form with arguments. So
`tools/check_log_format.py` is an AST check with a `# lazy-log:` marker for a measured hot path, a CI step and a test.
Proved it can produce the other answer: run on the pre-change tree it finds all 71.

### Copilot and the deliberate review on #72

Copilot's four comments were all valid, and the fourth was a process miss of mine: a new tool is a "significant
increment" in the definition of done and needs `/local-review diff`, which I had marked skipped. The review scored
Error handling 6 and found more: the checker failed open on a file that did not parse (a BOM was enough), a literal
`%%` before a placeholder (`"100%%%s"`) hid the call, the logger test missed `logging.getLogger(...)` and wrongly
flagged `blog.info`, numeric `i % 10` counted as a message, and a marker after a `# noqa` did not count. Each was
reproduced against the committed checker before the fix, and the new fixtures fail on the old checker (all six
reviewed cases are answered wrongly by it). One real defect in the conversions: a log call rebound the typed
`encoder` parameter to a string in `cook.py`; renamed. The known gaps (a logger under another name, a method held in
a variable, a template in a variable) are now written in the module docstring and pinned by tests rather than implied.

### Owner: "agreed, let's base on the Blender config (we can iterate from there if needed) - go on G4"

G2 closed on the evidence I had looked up before asking: Blender 5.2's installed `config.ocio` carries ACEScg,
AgX, ACES 1.3 and 2.0, Khronos PBR Neutral and a False Color view, so no view is rolled by hand; its

roadmap's 'CC0' is a memory until the upstream licence is read: recorded as open inside the decision.

G4: the stated trigger (the standards pass) had passed on 2026-09-27, so the gate was already due. The roadmap had
already fixed the six things the design must cover; the draft makes them concrete and adds what the project has
learned since. Three points shaped it. The exact quad-sphere probes are the **oracle** kind of check and move in
as cases rather than being replaced. A comparison is of three kinds (oracle, regression, parity), one machinery.
And the Maya adapter has a hard limit nobody had written down: its capture is an 8-bit display-referred
playblast, so the roadmap's 'raw scene-referred first' endpoint does not exist for Maya today. The design gives
each host a capture level (L2 scene-referred, L1 display-referred, L0 none) and makes the Maya float-capture
spike the first Maya step. Six questions are left to the owner, each with a recommendation.

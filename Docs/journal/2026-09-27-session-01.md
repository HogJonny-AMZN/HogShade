### A NaN in the v1 GPU test was the test, not the shader

`legacy_v1_evaluate_light` returned NaN for a few rows. The rows were the ones where the random view
direction equalled the light direction after the facing flip, so the half vector was zero length. The
test's view vectors now use a different seed offset from its light vectors. Worth remembering before
blaming a shader: the harness generates its own degeneracies.
→ `tests/core/test_legacy_v1_gpu.py`

### The resident worker keeps the scene, and keeps the history log open

The v1 Maya check ran on the same `hogshade_maya_gui` worker as the v2 check, so the sphere from the
previous check was still in the scene. Every check now starts with `cmds.file(new=True)`. A second
effect surfaced after the PR was pushed: the check leaves Script Editor history mirroring on, so the
worker kept appending to the committed `maya-history.log` and held it open; `git checkout` could not
restore it. Fixed in this branch by turning history mirroring off in `finish` and `fail`.
→ `tools/maya/_session.py` · `tools/maya/ibl_check.py`

SpriteJammer's skill is repo-agnostic by design: it discovers standards at run time and scores a

### Owner: the case for BATS versus an MCP, made visible as we go

*"BATS is repeatable, durable, reduces discovery and churn over time. It's a new paradigm, it's an
agentic pipeline, it just makes sense ... so let's make it clear as we go where it's made the most
sense and an impact."* The record already holds the first instances: the PR F Maya gate that
standalone launches could not pass reliably (a minute of startup, exit 139 one time in three, idle
Mayas left by a launcher bug, two GUI Mayas crashing each other, a retry loop that killed the owner's
worker) passed as one job on the resident worker; the v1 check reused that job with one parameter;
the cook runs as a job on the Python worker; and the profile, environment files, launcher and job
manifests are committed, so the discovery (worker types, environment layering, the base-profile
inheritance trap) happened once. The MCP is the agent's doorway to the same queue, not a rival
pipeline; an ad-hoc DCC MCP would rediscover the session every time and hold nothing durable. The
journal now carries a `→ BATS:` line whenever the orchestrator made the difference, and the
knowledge file keeps the running summary.
→ `Docs/knowledge/job-orchestrator.md` "Where it made the difference" · decision log · journal README

### Increment 1: task 5, the seed documents, built in the template

Task 5 was built in four pull requests in `ai-first-template` (#3 to #6, 159 tests): the seeded documents and a `{{today}}` token in
`init`; the framework ledger (27 entries) and the project ledger; the reconciled standards; the pull request template and the two
review skills. Every part was reviewed by a fresh-eyes pass that checked the content against its sources, and Copilot read the
first three.

What changed what I believed. The ledger was the clearest case: a merge that looks faithful read, on a second pass against the
sources, as a draft with an invented incident in it (a bell character from this very build, taken for a source entry), a
preamble that claimed more than the evidence, two lessons lost in the merging and three entries so compound that a skimming
agent would miss the part that applied. A managed test that checked the project ledger was empty would have turned red in every
repository the first time a project used its own ledger. The review of the standards found a core file that depended on a
module that can be switched off, which `init new` now refuses. And the owner's question "does the template get its own
glossary?" showed that the template's pull requests had been using the words payload, manifest, seed and made repository with
no glossary row in the repository that exists to enforce that rule; it has one now.

Plan task 5's written verification (`check_docs.py` clean on a made repository) cannot run until the checker exists, so it moved to
task 6, with the seed tests as its stand-in. The findings are in the spec's *What the build found*.

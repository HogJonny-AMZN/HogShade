### The host map: what the schema does not know

Reading the shell against the schema settled what a generator needs beyond the type files: the host's
identifiers (`materialRoughness`, `useRoughnessMap`), labels, UI orders and groups, one Maya semantic
(`OPACITY`), and the flip vector exposed as three sign dropdowns. Everything else the shell declares
(defaults, ranges, choices, colour spaces) the schema already carries, and S1's files already match the
shell's values, which is why the spec can forbid any value change in S2. The map is per host, keyed by
parameter name, and a value the schema knows is a finding in the map. Decided to retire the shell's
four UI macros for explicit declarations: the generator's output is then the thing the S1 union test
parses, with no macro layer to keep in step.
-> the spec, "The host map" and "The generated Maya block"

### Owner: "it's not just that we declare logging / loggers ... the point is that logging is meaningful to humans, as well as an artifact for ai spelunking and troubleshooting"

Said on the standards PR, which had given 30 modules a logger and none of them a log line. The correction
is the one that matters: a declared logger satisfies the header rule and nothing else; the record of a run
is what a person reads afterwards and what an agent diagnoses a failed job from without re-running it.
`python.md` gained "What a log is for": inputs named at the start, every artifact and its path, every
decision taken on the caller's behalf (a migration, a parameter the host cannot carry, a compiler missing)
at INFO or WARNING, per-item detail at DEBUG, entry points configuring a timestamped format once. The
code followed: `load()` logs a migration, `convert()` its losses, `bind()` what the host cannot take, the
wgpu host its adapter and environment, `build_shaders` each artifact with its digest and a missing
compiler as a warning, the jobs their start and their artifacts, the two material tools their outputs.
Two tests read the record back through `caplog`. A viewport run now prints eight lines that say what was
rendered from what, on which adapter, and where it went.
-> `Docs/standards/python.md`, "What a log is for"; memory `feedback-meaningful-logging`

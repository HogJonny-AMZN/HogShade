### T1 built (the owner's "go", continued)

Built on `feat/t1-content-standard` stacked on the spec's #50, in one pass: the texture rules as data, the
check, the generated tables, the standard, the pointers. Two things decided while building: the table
check is `check_suffixes`, not `check_table`, because the package already exports a `check_table` for
conversion tables and one name for two checks is synonym drift; and `parse_name` parses any stem that meets
the grammar and reports an unknown suffix separately from a name outside the grammar, so a typo in a suffix
reads as a typo, not as a foreign file. The content check passes on the repository with zero textures,
which is honest and vacuous for files and real for the table: fourteen suffixes against the schema's
fourteen texturable parameters, and a test that fails the moment the schema gains one. The standard's
tables come out of `textures.py` through the same markers mechanism as the Maya shell, so a suffix edit is
one place. `.gitattributes` tracks `content/textures/**` PNG and TIFF in LFS from now, so the first set
lands tracked rather than retro-fitted.
→ the plan ticked with its table; the spec amended; board; docs map; handoff

### The pre-PR review of T1

Round one: lowest 5, and the 5 was earned. The standard put texture sets under `content/textures/<set>/`
while S1 refuses any `..` in a document's texture path and the binding check confines a document to
`content/materials/`: no document could bind a texture where the standard said textures live, and the
test fixture had hit exactly that and filtered the findings away instead of raising it. The decision,
recorded in the spec's amendments and the standard: a set a document binds lives beside the document,
`content/materials/standard/<family>/<set>/`, bound as `<set>/T_<set>_BC.png`; `content/textures/` stays for
sets no document binds yet (the calibration tiles). The content roots are both and every rule applies to
each. The rest: the binding check held every document to the standard's suffix table (a legacy v2 document
binding `roughness` to `_R` was a false positive), now logged and skipped; `cooked` was tested on the
absolute path (a checkout under a directory named cooked would flag every file), now relative to the content
root; an LFS pointer where a PNG should be skipped the resolution silently (CI's checkout, always), now
logged as unverified; `jpg` was in the spec and not in the formats, now a finding wherever it lands; a bool
passed as a resolution. The clean-corpus test now asserts an empty finding list with no filter, and five
tests were added for the five false paths.
→ the spec's amendments; the standard; the design's section 4 (amended by reference); the plan's task 1 wording

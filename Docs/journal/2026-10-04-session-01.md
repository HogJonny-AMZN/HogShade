### Owner: "is ispc on the eval list?"; then the link to K0lb3's `ispc_texcomp_py`

It was, with a wrong note: I had it down as a C library needing a wrapper of ours. The owner found the
binding: MIT, on PyPI as `ispc_texcomp`, `compress_blocks_bc7/bc5/bc4` over an `RGBASurface` returning the
blocks as bytes, BC7 profiles from `ultrafast` to `slow`, and it resolves for this environment (1.0.1). That
is the owner's BATS bar met on paper: a Python module, no subprocess. A two-minute probe with `uv run --with`
on a synthetic 2K map: BC7 basic 4.4 s and fast 1.8 s per 2048x2048 on one core, BC5 0.01 s, BC4 under 0.01 s, byte-identical on a second run. The spike row names it the leading candidate; the spec's seam gains the
block-bytes shape it returns and a block-compressed DDS writer. The spike still measures quality against
`texconv` and the Linux wheel before it is the default.
→ board (the spike row corrected); the spec's question 2

### Owner: "this approach seems open source and if it does everything we need, we could end the spike with it (and log the other options for research and evaluation later)"

Checked the four facts that decide it instead of running a spike: PyPI ships `cp311-abi3` wheels for
Windows, Linux (manylinux and musl, four architectures) and macOS; the licence is MIT; BC7 on a noisy 1K
gradient decodes back at 34 to 38 dB across the profiles through `texture2ddecoder`; on a 2048x2048 map BC7 basic 4.4 s and fast 1.8 s on one core, BC5 0.01 s, BC4 under 0.01 s, byte-identical on a second run; quality through a decoder on a noisy 1K gradient, BC7 fast 36.9 dB and basic 37.7 dB, BC5 and BC4 48.6 dB. The BC4 and
BC5 numbers came back as nonsense the first time, so a block was decoded by hand: the encoder had read the
RGBA surface as if it were one byte per pixel. ISPC's BC4 takes an R8 surface and BC5 an RG8 surface, stride
to match; fed that way, a 4x4 ramp decodes with the error BC4 allows. That fact is in the spec so the build
does not rediscover it. The spike row is struck as closed on the pick; the other encoders are an Icebox row
with what each would be for. Copilot's ten findings on #53 fixed in the same commit: five PNG filter types,
not four; grey-alpha in the test matrix; the `_O`-into-alpha packing dropped (no sidecar field for it); `_DN`
out of the source row and the macro normal kept as the design says; the job registered in `JOB_MODULES`;
the handoff's reading-order line, stale again (ledger entry 15, the second time in two days); the board's
